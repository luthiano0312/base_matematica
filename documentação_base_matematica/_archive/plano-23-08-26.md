# Plano — Materiais de Estudo (fluxo completo)
**Data:** 23/08/2026
**Contexto para o agente:** este arquivo é um plano de implementação para a feature "Materiais de Estudos" do projeto Ceará Científico. Leia `AGENTS.md` na raiz do repo antes de começar — ele descreve as convenções do projeto (guards de auth separados, Services para lógica de negócio, camada de serviços do frontend, RN/RF/RNF citadas no código). Este plano assume essas convenções e não as repete em detalhe.

**Prazo:** 7 dias, ~2h/dia. Trabalhe em fatias verticais, na ordem abaixo — cada fatia deve terminar em um estado demonstrável (algo funcionando ponta a ponta), mesmo que incompleto. Não avance para a fatia seguinte sem que a anterior esteja funcional.

## Decisões já tomadas (não re-discutir, apenas implementar)

- **Schema:** nova tabela `study_materials` (ela ainda **não existe** no backend — nem migration, nem model, nem controller, nem rotas). Colunas: `id`, `title` (string), `content` (text, HTML), `topic_id` (FK nullable, `topics.id`), `content_id` (FK obrigatória, `contents.id`), `video_url` (string, nullable), timestamps.
- **Relação com Conteúdo/Tópico:** FK simples 1:1 (não N:N como em `questions`). `topic_id`, quando presente, deve pertencer ao `content_id` do mesmo registro — mesma regra de RN16, validada no backend. No form, o select de Tópico é dependente do Conteúdo selecionado (mesmo padrão de `CadastroQuestoesPage.tsx`, mas single-select em vez de multi-select).
- **Obrigatoriedade:** `title` e `content_id` sempre obrigatórios. Entre `content` (artigo) e `video_url` (vídeo), **pelo menos um dos dois** deve estar preenchido — nunca os dois vazios.
- **Pipeline de conteúdo rico:** `content` usa o mesmo pipeline HTML já existente para `statement`/`text_resolution` de `questions` — Tiptap (admin) → HTML → DOMPurify (client do aluno) → KaTeX auto-render (RN21/RN22). Não usar Markdown. Reaproveitar o componente `RichTextEditor` (`frontend/src/features/admin/cadastro-questoes/RichTextEditor.tsx`) diretamente — ele já embute Tiptap + MathLive (fórmulas) + upload de imagem, sem necessidade de refatoração.
- **Upload de imagem:** reaproveitar `UploadImageController`/`SupabaseStorageService` como já estão — são genéricos, sem acoplamento a `questions`. Nenhuma mudança necessária no backend de upload.
- **Vídeo:** `video_url` sem validação de domínio no cadastro (mesmo padrão simples de `video_resolution_url` em `questions`, só `type="url"`). Na tela do aluno, extrair o video ID do YouTube a partir de qualquer formato de URL (`watch?v=`, `youtu.be/`, `embed/`, com ou sem parâmetros extras) e renderizar como `<iframe>` embutido. **Fallback:** se a extração do ID falhar, mostrar um link simples "assistir vídeo" em vez de não mostrar nada.
- **Acesso do aluno:** público, sem autenticação (RN01/RF02) — rota de leitura fora do grupo `auth:sanctum`. CRUD (criar/editar/deletar) exclusivo do guard `admin`.
- **Delete:** direto, sem endpoint `can-delete` — não há nenhuma FK de outra tabela apontando para `study_materials`, então não há risco de órfão.
- **Nomenclatura de rotas:** backend em inglês, consistente com `questions` (`GET/POST /api/study-materials` público de leitura; `GET/POST/PUT/DELETE /api/admin/study-materials` sob guard admin). Frontend com rota visível em português: `/materiais-de-estudo`.
- **Resource:** um único `StudyMaterialResource` (sem versão "pública" separada como em `PublicQuestionResource`) — não há gabarito nem dado sensível a esconder aqui.
- **Filtro do aluno:** por Conteúdo e Tópico (dependente), reaproveitando o padrão visual já usado no filtro de Questões — sem os campos de Dificuldade/Quantidade (não se aplicam).
- **Paginação:** nenhuma nessa rodada — listar tudo de uma vez, mesmo padrão de `getContents()`/`getTopics()` hoje.
- **Navegação:** nova seção no menu do painel admin, mesmo nível hierárquico de "Questões". Do lado do aluno: reativar o atalho "Materiais de estudo" no Dashboard (hoje com `onClick` vazio — parte do item M12 do audit) e adicionar o link no menu hambúrguer da Home (hoje ausente, documentado como pendente em `Fluxo_de_Navegacao.md`).
- **Testes automatizados:** pulados nessa rodada, deliberadamente — dívida técnica consciente (equivalente às decisões já registradas em `Pendencias.md`). Validar manualmente os casos: criar só com artigo, só com vídeo, com os dois, e confirmar que "nenhum dos dois" é rejeitado pela validação.
- **Rede de segurança / corte de emergência:** se faltar tempo antes da avaliação, é aceitável entregar o vídeo como link simples em vez de iframe embutido — mas o fluxo ponta a ponta (admin cadastra → aluno vê) precisa estar funcional. Não é aceitável entregar só backend sem nenhuma tela funcionando.

## Fatia 1 — Esqueleto ponta a ponta (só artigo, sem vídeo, sem edição/delete)

**Objetivo:** provar que o pipeline inteiro funciona o quanto antes.

Backend:
1. Migration `study_materials` (title, content, topic_id nullable FK, content_id FK, video_url nullable, timestamps)
2. Model `StudyMaterial` com `$fillable` e relações (`belongsTo Content`, `belongsTo Topic`)
3. `StudyMaterialResource`
4. `StoreStudyMaterialRequest` — validar: `title` obrigatório, `content_id` obrigatório e existente, `topic_id` opcional mas, se presente, deve pertencer ao `content_id` informado (regra análoga a RN16), e "pelo menos um entre `content`/`video_url`" preenchido
5. `StudyMaterialController@store` e `@index` — rota admin sob guard `admin`
6. Rota pública `GET /api/study-materials` (sem guard) devolvendo a listagem via `StudyMaterialResource`

Frontend:
7. Form admin novo e simples (ex: `frontend/src/features/admin/materiais-estudo/CadastroMaterialPage.tsx`) — campo título, `<RichTextEditor />` para o artigo, selects de Conteúdo/Tópico dependentes (sem vídeo ainda nesta fatia)
8. Listagem simples do aluno (ex: `frontend/src/features/materiais-estudo/MateriaisListPage.tsx`) — título + preview do conteúdo, sem filtro ainda
9. Rotas em `App.tsx` (`/materiais-de-estudo` para o aluno, rota correspondente no painel admin) + entradas de navegação básicas (menu admin, atalho do Dashboard, link no menu hambúrguer da Home)

**Checkpoint desta fatia:** criar um material via admin e vê-lo aparecer na listagem pública do aluno.

## Fatia 2 — Vídeo

10. Campo `video_url` no form admin (`type="url"`, mesmo padrão usado em `CadastroQuestoesPage.tsx` para `video_resolution_url`)
11. Garantir que a validação backend de "pelo menos um dos dois" cobre corretamente os três casos: só artigo, só vídeo, os dois
12. Tela de leitura do aluno: função de extração do video ID (cobrindo `watch?v=`, `youtu.be/`, `embed/`) → renderizar `<iframe>`; se a extração falhar, renderizar link simples "assistir vídeo" apontando para a URL crua

**Checkpoint desta fatia:** criar material só com vídeo, só com artigo, e com os dois; confirmar que tentar salvar sem nenhum dos dois é rejeitado com mensagem clara.

## Fatia 3 — Edição e delete

15. Frontend admin: modo edição reaproveitando o mesmo form da Fatia 1 (padrão de `CadastroQuestoesPage.tsx`, que já suporta criar/editar na mesma página via parâmetro de rota); botão de exclusão na listagem admin
